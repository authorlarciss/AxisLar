# AxisLar

Многомерное ядро хранения: объекты существуют не в папке и не в строке
таблицы, а в пространстве координат.

AxisLar — абстрактное ядро для многомерных данных, независимое от
конкретного бэкенда (SQL, Markdown, графовая БД, память). Пользователь
задаёт **оси** (измерения) и заполняет **объекты** значениями по этим
осям — **фасетами**. Ось — это способ спросить «где», без привязки к тому,
как это хранится.

## Модель в трёх абзацах

**Оси.** Ось — именованное измерение схемы: `theme`, `source`,
`year_opened`. Типов три: *categorical* (конечное множество значений),
*measurable* (числа, пригодные для сравнения) и *reference* (указатель на
`id` другого объекта). Оси добавляются на лету: старые объекты не
переписываются, они просто становятся разреженными.

**Объекты.** Универсальная единица данных — эдит, заметка, видео, что
угодно. У неё есть `id`, **скаляры** (`title`, `description` — для
отображения и поиска, не для аналитики) и **фасеты** — разреженный словарь
`ось → значение(я)`. Мультизначность разрешена: у объекта может быть
несколько `theme`.

**Запросы.** Запрос — дерево фильтров по осям; в v0 исполняется
конъюнкция (AND). Выдача — идентификаторы или объекты. Отношений как
отдельной сущности нет: всё, что ссылается на другой объект, — фасет на
оси с типом `reference`.

## Что AxisLar не делает

- Не знает про файлы, SQL, Obsidian и папки. Бэкенды — сменные реализации.
- Не рисует UI и не содержит CLI-логики в ядре (`gamma` — клиент).
- Не имеет реестра плагинов в v0: только швы (интерфейсы + контрактные тесты).
- Не поддерживает даты как отдельный тип оси (v0): measurable — только числа.
- Не умеет OR/NOT в v0, хотя AST запроса к этому готов.

## Принципы

1. **Семантика важнее бэкенда.** Сначала договариваемся, что значит
   оператор на разреженных и мультизначных данных, потом пишем хранение.
2. **Разреженность первоклассна.** Отсутствие значения по оси — не пустая
   строка и не `None`, а отдельное состояние с собственной семантикой.
3. **Одна семантика на все бэкенды.** Контрактный набор тестов
   параметризуется по реализации; второй бэкенд обязан его пройти целиком.
4. **Расширение через данные, а не через код.** Новая предметная область —
   это новые оси, а не новый класс в ядре.
5. **Швы раньше реестров.** Интерфейс + контрактные тесты дешевле и
   устойчивее «плагинной системы», написанной заранее.

## Структура

| Модуль | Роль в ядре |
|--------|--------------|
| `alpha` | DTO и словарь домена: `Entity`, `AxisDefinition`, `FacetValue`, `StorageSchema`, `Query`, `QueryResult`, `Artifact`, `Capability`, `DomainError` |
| `beta` | Доменные правила: `validate_axis/scalar/entity/query` (чистые функции) |
| `delta` | Хранилище: порт `IStorageEngine` (объекты + артефакты), эталонный `MemoryStorage`, ошибки исполнения |
| `iota` | Контрактные наборы для внешних адаптеров (`run_storage_contract`, `run_source_contract`) |
| `sigma` | Логирование |
| `mu` | Версии: `__version__`, `CONTRACT_VERSION` |
| `psi` | Сборка ядра: `build_core()`, фасад `Core`, контракты модулей |

Продукта и плагинов в этом проекте нет: `Core` — стабильный вход, продукт
(интерфейс + реестр плагинов) и бэкенды-плагины — отдельные проекты.

Корневые каталоги: `tau/` — тесты, `eta/` — инструменты разработки (вне
дистрибутива), `lambda/` — документация, `omega/` — сборка и релиз
(Docker, операционные скрипты).

Домен описан нормативно в `lambda/DOMAIN.md`, план реализации — в
`lambda/PLAN.md`, решения — в `lambda/adr/`.

## Быстрый старт

```bash
make install   # uv sync + pre-commit hook
make check     # формат, линт, контракты, типы, тесты
make run       # собрать ядро и показать состояние
```

Использование из кода:

```python
from nu.psi import build_core
from nu.psi.contracts.alpha import AxisDefinition, AxisKind, Entity

core = build_core()  # эталонное in-memory хранилище
await core.add_axis(AxisDefinition(name="theme", kind=AxisKind.CATEGORICAL))
await core.upsert(Entity(id="e-1", kind="edit"))
result = await core.query(Query())
```

## Происхождение

Ответвление шаблона [BaseLar](https://github.com/authorlarciss/BaseLar)
v0.7.x (Hellenic Architecture). Предыдущий проект VaultLar остановлен:
он смешивал модель данных с конкретным хранилищем (Markdown + SQLite +
схема Obsidian). AxisLar начинает с модели, а хранение подключает позже.

## Установка

Только из артефактов релиза — в репозитории пакет называется `nu`, а в
wheel он переименован в `axislar_core`:

```bash
pip install axislar_core-0.10.0-py3-none-any.whl
```

`pip install git+...@vX.Y.Z` не поддерживается: поставит пакет `nu` и
столкнётся с другими проектами экосистемы. Подробности — раздел «Релиз и
деплой» в `lambda/VERSIONING.md`.

## Статус

`0.10.0` (контракт 5) — ядро. Модель и проверки, порт хранилища
(tombstone-семантика, артефакты по хэшу), порт источника, семантика
синхронизации (`plan_sync`: create/update/move/tombstone/resurrect),
провенанс фасетов, переиспользование производных фактов по `content_hash`,
два контрактных набора (`run_storage_contract`, `run_source_sync_contract`),
клиенты/фичи с разрешением вариантов (`resolve_feature`), деплой-переименование
пакета.
Продукт (AgoraLar) и плагины — отдельные проекты, см. `lambda/PLAN.md`.
