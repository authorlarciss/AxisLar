# Архитектура AxisLar (ядро)

Документ описывает **ядро**. Продукт (интерфейс, реестр плагинов) и
плагины (бэкенды хранилищ, источники, анализаторы) — отдельные проекты,
которые зависят только от контрактов ядра.

## Что такое ядро

Ядро умеет ровно три вещи:

1. описывать измерения (`AxisDefinition`, `ScalarDefinition`) и объекты
   (`Entity` с фасетами);
2. проверять данные и запросы против схемы (`beta`);
3. хранить объекты и исполнять запросы через порт `IStorageEngine`
   (эталонная реализация — `MemoryStorage`).

Ядро не знает про файлы, сеть, CLI, конфиги и плагины. `build_core()`
поднимается без аргументов — на in-memory хранилище.

## Модули

| Модуль | Роль |
|--------|------|
| `alpha` | DTO и словарь домена: оси, фасеты, объекты, запросы, `Capability`, `DomainError` |
| `beta` | Доменные правила: `validate_axis/scalar/entity/query` — чистые функции |
| `delta` | Хранилище: порт `IStorageEngine`, эталонный `MemoryStorage`, `StorageQueryError` |
| `iota` | Контрактные наборы (`run_storage_contract`, `run_source_sync_contract`) и политика `entity_id_for(source_id, key)` |
| `sigma` | Логи и контекст запроса |
| `mu` | Метаданные: `__version__`, `CONTRACT_VERSION` |
| `psi` | Композиционный корень: контракты, фасад `Core`, `build_core()` |

Правило: **модуль — не слой** (ADR-0015). Модуль владеет понятием целиком:
порт и его эталонная реализация живут в одном модуле. Порт существует для
**внешних** реализаций (плагинов), а не как шаблон для другого модуля того
же проекта.

## Границы внутри модуля

- `public/` — то, что можно импортировать снаружи модуля.
- `_internal/` — реализация; доступ только через `public/resolver.py`.
- `psi/contracts/<module>.py` — единственный путь для других модулей.
- `__init__.py` — только docstring, реэкспорт — строго `from X import Y as Y`.

Проверяется механически: `make lint-imports` (правила в `pyproject.toml`).

## Ядро и внешний мир

Единственный вход для потребителей — фасад `Core`:

```python
core = build_core()  # или build_core(storage=plugin_backend)
await core.add_axis(axis)
await core.upsert(entity)
result = await core.query(query)
```

Что экспортируется как контракт (через `nu.psi.contracts.*`):

| Контракт | Где | Назначение |
|----------|-----|------------|
| DTO модели | `alpha` | язык обмена: продукт, плагины, клиенты |
| `validate_*` | `beta` | проверки без исполнения, ошибки — значениями |
| `IStorageEngine` | `delta` | порт для бэкендов-плагинов (tombstone-семантика: `list_entities(include_deleted)`) |
| `IEntitySource` | `delta` | порт источника (`describe`, `scan`) |
| `StorageQueryError` | `delta` | отказ движка на невалидированном запросе |
| `plan_sync`/`apply_plan`/`merge_entity`/`inherit_derived` | `beta` | синхронизация: план, слияние по владельцам, reuse по хэшу |
| `Core`, `build_core` | `psi` | вход в ядро |

`CONTRACT_VERSION` (в `mu`) — версия этой поверхности. Меняется при
ломающих изменениях; плагины и продукт объявляют совместимый диапазон.

## Чего в ядре нет и почему

- **Продукт**: CLI, HTTP, реестр плагинов, конфигурация, файлы состояния.
  Это отдельный проект; ядро не должно зависеть от интерфейсов.
- **Плагины**: `JsonStore`, `SqliteStore`, адаптеры внешних БД, анализаторы.
  Они реализуют контракты ядра и проверяются контрактным набором тестов.
- **Пайплайны и шины событий**: домен не про поток обработки (ADR-0014).

## Поток данных

```
внешнее хранилище (файлы, SQL, ...)
        │  адаптер-плагин (IEntitySource, позже)
        ▼
      Entity + фасеты  ──валидация(beta)──▶  ядро (Core)
        ▲                                      │
        │                                      ▼
   продукт / клиенты  ◀──QueryResult──── IStorageEngine (delta или плагин)
```

Ядро хранит **результаты анализа** внешних хранилищ, а не сами внешние
хранилища: адаптеры приводят внешние данные к `Entity`, ядро отвечает за
их согласованность и запросы.

## Правила, которые нельзя нарушать

1. Между модулями — только `psi.contracts`.
2. Все интерфейсы — `async def`; синхронная реализация просто без `await`.
3. Ошибки домена — значения (`DomainError`), исключения — только на
   границе исполнения (`StorageQueryError`).
4. `_internal` не виден никому, кроме `resolver` своего модуля.
5. Ядро не импортирует продукт и плагины: зависимость идёт только внутрь.
