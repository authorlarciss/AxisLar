# Домен AxisLar (нормативное описание)

Документ фиксирует семантику модели. Код обязан соответствовать этому
файлу; расхождение — дефект. Решения и их обоснование — в ADR-0009…0013.

## 1. Оси

`AxisDefinition`:

| Поле | Тип | Смысл |
|------|-----|-------|
| `name` | `str` | Имя оси. Плоское, не иерархическое. Неизменяемо: переименование = новая ось |
| `kind` | `categorical` \| `measurable` \| `reference` | Тип значения |
| `multi` | `bool` | Разрешено ли несколько значений на объект |
| `target` | `str \| None` | Для `reference`: ожидаемый вид цели (kind объекта) |
| `strict` | `bool` | Для `categorical`: закрыт ли словарь значений |
| `values` | `tuple[str, ...]` | Для `categorical`: словарь допустимых значений (обязателен при `strict`) |
| `description` | `str \| None` | Человекочитаемое пояснение |

Инварианты:

- **A1.** Имя оси уникально в пределах `StorageSchema` и не может быть пустым.
- **A2.** `target` задаётся только для `reference`, иначе `None`.
- **A3.** `strict` осмыслен только для `categorical`; для остальных — `False`.
- **A4.** Ось нельзя удалить или переименовать в v0. Добавление — можно
  (см. §2 разреженность).
- **A5.** `values` задаётся только для `categorical`; при `strict=True`
  словарь непуст; дубликатов в словаре нет. При `strict=False` пустой
  словарь означает «открытый словарь».

## 2. Разреженность и динамические оси

Объект имеет значение по оси либо **не имеет** его. Это три различных
состояния, и они не смешиваются:

1. значение есть (`FacetValue` присутствует);
2. значения нет (ключ оси отсутствует в фасетах) — «нет данных»;
3. значение есть, но пустое (например, `title = ""`) — это скаляр, не фасет.

Добавление новой оси не изменяет существующие объекты: они становятся
разреженными по этой оси. Бэкенд не имеет права материализовывать
отсутствующие значения (никаких `NULL`-строк, «дефолтов» или пустых
списков) — иначе состояние 2 неотличимо от состояния 1.

## 3. Объект

`Entity`:

- `id: EntityId` — UUIDv5 от естественного ключа (`source`, `key`);
  детерминированный, чтобы повторный импорт не создавал дубликатов.
- `kind: str` — вид объекта (`edit`, `note`, `video`, ...). Цель для
  `reference.target`.
- `scalars: dict[str, str]` — только те ключи, что объявлены в
  `StorageSchema.scalars`.
- `facets: dict[str, list[FacetValue]]` — разреженный словарь; ключ — имя
  оси, значение — непустой список для `multi=True` и список из одного
  элемента для `multi=False`.
- `derived_by: dict[str, Provenance]` — происхождение производных фасетов
  (`plugin`, `version`, `at`). У пользовательских значений записи нет.

`FacetValue` — дискриминированный union по `kind`:

- `CategoricalValue(value: str)`
- `MeasurableValue(value: float, unit: str | None)`
- `ReferenceValue(target: EntityId)`

Инварианты:

- **E1.** `id` уникален в хранилище; повторный `upsert` с тем же `id` —
  замена, а не дубликат.
- **E2.** Ключи фасетов обязаны существовать в схеме (ошибка `UnknownAxis`).
- **E3.** Тип значения обязан совпадать с типом оси (ошибка `TypeMismatch`).
- **E4.** Для `multi=False` — ровно одно значение (ошибка `CardinalityViolation`).
- **E5.** `reference`-значение обязано указывать на существующий `EntityId`
  (на запись; ошибка `DanglingReference`, политика — ADR-0011).
- **E6.** `categorical` при `strict=True` допускает только значения из
  словаря оси (ошибка `UnknownCategory`).

## 4. Запрос

`Query` — дерево: `{"all": [Filter, ...]}`. В v0 исполняется только `all`
(конъюнкция); `any` / `not` зарезервированы в AST, но возвращают
`UnsupportedQuery`, если встречены.

`Filter` — кортеж `axis`, `op`, аргументы. Операторы:

| Тип оси | Операторы | Смысл |
|---------|-----------|-------|
| `categorical` / `reference` | `contains` | среди значений есть указанное |
| `categorical` / `reference` | `any_of` | есть хотя бы одно из перечисленных |
| `categorical` / `reference` | `none_of` | нет ни одного из перечисленных |
| любая | `exists` / `not_exists` | значение по оси есть / отсутствует |
| `measurable` | `eq`, `gt`, `lt`, `gte`, `lte`, `between` | сравнение чисел |
| скаляр | `scalar_eq` | точное совпадение |

`!=` не вводится: при мультизначности он неоднозначен (см. таблицу §5).

**Валидация отделена от исполнения.** `validate_query(query, schema,
capabilities)` возвращает список `DomainError` (пустой — запрос исполним).
Проверяется: существование оси/скаляра, совместимость оператора с типом
оси, попадание значений в `strict`-словарь и наличие у бэкенда требуемой
`Capability`. Движок исполняет уже проверенный запрос; `plan`-объект
появится, когда понадобится (v0 обходится без него).

## 5. Семантика отсутствующих значений (обязательная таблица)

Пусть у объекта нет значения по оси `X`.

| Оператор | Результат для объекта без значения по `X` |
|----------|-------------------------------------------|
| `contains` | **false** |
| `any_of` | **false** |
| `none_of` | **true** |
| `exists` | **false** |
| `not_exists` | **true** |
| `eq`, `gt`, `lt`, `gte`, `lte`, `between` | **false** (нечего сравнивать) |
| `scalar_eq` | **false** |

Для мультизначных осей `contains`/`any_of` — «хотя бы одно значение
удовлетворяет», `none_of` — «ни одно значение не входит в множество».
Именно поэтому `none_of` и «нет значения» согласованы: отсутствие значений
не содержит ничего запрещённого.

## 6. Результат запроса

`QueryResult`: `ids: list[EntityId]`, `total: int`, `limit: int | None`,
`offset: int`. Порядок детерминирован (по `id`), если не задан иной.
Полные объекты — отдельным вызовом `fetch_many(ids)`; запрос возвращает
только идентификаторы.

## 7. Ошибки

`UnknownAxis`, `TypeMismatch`, `CardinalityViolation`, `DanglingReference`,
`UnknownCategory`, `UnsupportedQuery`, `UnknownScalar`. Ошибки — значения
(`DomainError`), не исключения на границе API: клиент обязан различать
«нет данных» и «запрос невалиден».

## 8. Не входит в v0 (осознанно)

- Даты/интервалы как тип оси (числа — да; временной тип — позже).
- Иерархические оси, наследование значений, дефолты.
- OR/NOT в исполнении (AST готов).
- Удаление осей, переименование, миграции схемы.
- Транзакции, конкурентная запись, индексы.

## 9. Синхронизация источника (ADR-0016)

Объект, пришедший из источника, несёт `Origin(source_id, key, content_hash,
hash_algo)`; удалённый — `deleted_at` (tombstone).

| Ситуация | Правило |
|----------|---------|
| Добавлен | `create` |
| Не изменился (тот же ключ и хэш) | без действий |
| Отредактирован (тот же ключ, другой хэш) | `update`, `id` сохраняется |
| Переименован (новый ключ, тот же хэш, единственный кандидат) | `move`: `id` **сохраняется**, меняется `origin.key` |
| Удалён | `tombstone` (`deleted_at`), только при полном скане |
| Вернулся | `resurrect` (`deleted_at` снимается) |
| Хэш совпал с несколькими объектами | конфликт, автоматического выбора нет; кандидаты не удаляются |
| Копия проекта | новый `source_id`; производные факты — из content-кэша (ADR-0017) |

Tombstone не участвует в запросах по умолчанию. Неполный скан
(`complete=False`) не порождает tombstone: сбой чтения не должен
превращаться в массовое удаление.
