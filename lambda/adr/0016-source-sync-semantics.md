# ADR-0016: Синхронизация источника — tombstone, move по хэшу, политика копий

## Контекст

Ядро хранит состояние проверенных проектов и должно уметь приводить его в
соответствие с источником. Наивная реализация («что пришло — записать») не
различает шесть принципиально разных случаев:

1. файл добавлен;
2. файл удалён;
3. файл переименован (то же содержимое, новый путь);
4. проект переименован/перемещён (меняются все пути сразу);
5. проект скопирован (другая копия того же содержимого);
6. файл отредактирован (тот же путь, другое содержимое).

Без явной семантики каждый случай обрабатывается по-своему в каждом
адаптере, и «одинаковые» объекты двоятся, а ручные правки затираются.

## Идентичность

- `id = UUIDv5(source_id, key)`, где `key` — стабильный ключ внутри
  источника (для файлового дерева — путь относительно корня источника).
  `source_id` **не выводится из пути**: хранится в маркере/конфиге проекта.
  Переименование папки проекта не меняет `source_id`, значит не меняет `id`.
- `content_hash` (+ `hash_algo`) хранится в `Origin`; для больших файлов —
  `size + частичный хэш (голова+хвост)`, алгоритм фиксируется в объекте.

## Решение по случаям

| Случай | Признак в плане | Действие | `id` | Ручные фасеты |
|---|---|---|---|---|
| Добавлен | `key` не встречался | `create` | новый | — |
| Не изменился | тот же `key`, тот же хэш | нет действий | — | сохраняются |
| Отредактирован | тот же `key`, другой хэш | `update` | тот же | сохраняются (источник меняет только свои фасеты) |
| Переименован | новый `key`, хэш совпал ровно с одним отсутствующим объектом того же источника | `move` | **старый** сохраняется, меняется `origin.key` | сохраняются, ссылки не рвутся |
| Удалён | объект источника не встречен, скан **полный** | `tombstone` (`deleted_at`) | тот же | сохраняются, объект скрыт из запросов |
| Вернулся | `key` совпал с tombstone | `resurrect` | тот же | сохраняются |
| Хэш совпал с несколькими | неоднозначный move | `conflict` (без действий) | — | требуют решения человека |
| Проект скопирован | другой `source_id` | новая ветка плана; производные факты — из content-кэша (ADR-0017) | новые | — |
| Один `source_id` у двух путей | продукт видит два корня с одним маркером | отказ + `source fork` | — | — |

Ключевые правила:

1. **Tombstone, а не delete.** Мягкое удаление сохраняет историю и ссылки;
   tombstone не участвует в запросах по умолчанию.
2. **Move сохраняет `id`.** Иначе каждое переименование ломает ссылки и
   теряет пользовательские фасеты.
3. **Неоднозначность не разрешается автоматически.** Два кандидата на move —
   конфликт, а не догадка.
4. **Неполный скан не порождает tombstone.** Если чтение источника упало на
   середине (права, диск, сеть), массовое «удаление» было бы катастрофой;
   `plan_sync(complete=False)` удаляет только «не удаляй».
5. **План — чистая функция.** `plan_sync(scanned, existing, policy)` не
   трогает хранилище; применение плана — отдельный шаг (`apply_plan`),
   поэтому семантика проверяется без бэкенда.

## Конфликты (ADR-0016, раздел «что считается конфликтом»)

- неоднозначный move (хэш совпал с несколькими);
- в скане два объекта с одним `key`;
- объект скана без `origin` или с чужим `source_id`;
- в скане есть `deleted_at` (источник не может отдавать tombstone).

Конфликт — данные (`SyncConflict`), а не исключение: план возвращает их
списком, вызывающий решает, применять ли остальное.

## Что меняется в модели

- `Entity.origin: Origin | None` — происхождение (источник, ключ, хэш).
- `Entity.deleted_at: datetime | None` — tombstone.
- `beta.sync`: `SyncPolicy`, `SyncAction`, `SyncConflict`, `SyncPlan`,
  `plan_sync`, `apply_plan`.
- Хранилище: запросы по умолчанию не видят tombstone (порт получает
  `include_deleted` на следующем шаге).

## Последствия

Плюсы: одинаковое поведение у всех адаптеров; переименования не рвут
ссылки; удаления обратимы; ошибки чтения не превращаются в массовое
удаление; семантика проверяется без хранилища.

Минусы: `content_hash` обязателен для детекта move (без него —
delete+create); tombstone нужно помнить в каждом бэкенде; конфликтные
ситуации требуют UI/CLI для разрешения.

## Статус

Принято.
