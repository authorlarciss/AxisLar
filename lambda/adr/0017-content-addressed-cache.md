# ADR-0017: Content-addressed кэш производных фактов

## Контекст

Факты об объекте делятся на два класса:

- **факты источника** — зависят от пути и имени файла (`owner`, `section`,
  `title`, `author` из имени, `path`). Дешёвые, пересчитываются каждым
  сканом.
- **факты содержимого** — зависят от байтов (`duration`, `resolution`,
  `codec`, превью, эмбеддинги, кластеры). Дорогие, требуют анализатора.

При копировании проекта (новый `source_id`) содержимое не меняется.
Пересчитывать анализ заново — платить полную цену за те же байты.

## Решение

1. **Кэш адресуется содержимым:** ключ
   `(content_hash, hash_algo, analyzer_id, analyzer_version, params)`.
   Версия анализатора в ключе обязательна: смена модели/параметров делает
   кэш невалидным, а не «немного неверным».
2. **Кэш всегда advisory.** Промах, сомнение, смена версии — пересчёт.
   Корректность модели от кэша не зависит; кэш влияет только на цену.
3. **Единица — объект, не папка/пакет.** Копия может быть частичной, файлы
   двигают между папками; хэш папки ломается сразу, хэш объекта — нет.
4. **Дедупликация артефактов.** Артефакт (превью, эмбеддинг) хранится по
   хэшу содержимого; два объекта с одинаковым содержимым ссылаются на один
   артефакт.
5. **Кэш живёт в том же хранилище** (секция `derived`): копия проекта
   переносится вместе с кэшем, `sync` не требует второго пути.
6. **Провенанс обязателен.** Производный фасет помечен
   (`derived_by: analyzer@version`), чтобы: (а) синхронизация не путала его
   с ручной правкой; (б) кэш мог отдать значение; (в) можно было
   инвалидировать при смене анализатора.

## Хэширование

- Быстрый путь: если `size` и `mtime` не изменились — хэш не пересчитывается.
- Иначе: `size + частичный хэш (голова 64 КБ + хвост 64 КБ)`, алгоритм
  записывается в `Origin.hash_algo`.
- Ложное совпадение частичного хэша означает «взяли чужое превью» —
  поэтому кэш advisory; при полном хэше (`hash_algo="full"`) риск снимается.

## Проверяемость

Контрактный тест: два источника с одинаковым содержимым; фейковый
анализатор считает вызовы. Второй источник не должен вызвать анализатор ни
разу — производные факты приходят из кэша. Тест не требует реального
видео: достаточно фабрики объектов с одинаковым `content_hash`.

## Альтернативы

- **Пересчитывать всё при копировании.** Просто, но дорого на больших
  архивах; копии — типовой сценарий (бэкапы, эксперименты).
- **Кэшировать по пути.** Ломается при переименовании/копировании —
  ровно те сценарии, ради которых кэш и нужен.
- **Доверять кэшу как источнику истины.** Опасно: смена анализатора или
  коллизия хэша дают тихо неверные данные. Отклонено: advisory.

## Последствия

Плюсы: копия проекта стоит O(чтение заголовков); дедупликация артефактов;
явная связь «дорогие факты ⟵ содержимое + версия анализатора».

Минусы: нужен провенанс (M8) до включения кэша; хэширование добавляет I/O
(смягчается fast-path по size/mtime); хранение кэша — ещё одна секция
хранилища, которую надо мигрировать вместе с моделью.

## Реализация (0.8.0)

Отдельной подсистемы кэша не понадобилось: **кэшем служит само
хранилище**. `inherit_derived(target, donors)` в `beta` ищет объекты с тем
же `content_hash` (кроме самого целевого и tombstone), берёт фасеты с
владельцем `analysis` и переносит их вместе с `derived_by`. Версия
анализатора живёт в `Provenance` донора, поэтому при смене версии
анализатор инвалидирует значения сам, сравнивая provenance.

При нескольких донорах выигрывает самый свежий `Provenance.at`; при
равенстве времени и разных значениях ось пропускается — неоднозначность не
разгадываем.

## Статус

Принято и реализовано в 0.8.0.
