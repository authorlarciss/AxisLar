# ADR-0018: Владелец фасета и политика слияния при синхронизации

## Контекст

Синхронизация обновляет объект из источника. Если писать скан целиком, то
любая ручная правка (исправленный `author`, добавленная заметка, результат
анализа) исчезает при следующем прогоне. Если, наоборот, ничего не
перезаписывать, источник перестаёт быть источником истины.

Нужен явный ответ на вопрос «чей это фасет».

## Решение

1. **Владелец фасета — часть модели.** `Entity.owners: dict[str, FacetOwner]`
   с тремя значениями: `source`, `user`, `analysis`. Ключи обязаны
   соответствовать существующим фасетам.
2. **Источник обязан размечать свои фасеты.** Контрактный набор
   (`run_source_contract`) требует, чтобы каждый фасет из скана был помечен
   `source`. Отсутствие разметки — ошибка адаптера, а не «по умолчанию
   пользовательский».
3. **Слияние при `update`/`move`/`resurrect`:**
   - фасет из скана — значение источника, владелец `source`;
   - фасет с владельцем `source`, которого в скане нет, — **удаляется**
     (источник авторитетен для своих осей; иначе значения «зависают»
     навсегда);
   - фасеты `user` и `analysis` сохраняются как есть;
   - `derived_by` сохраняется только для сохранившихся `analysis`-фасетов.
4. **Сравнение «изменился ли объект» — только по фактам источника:**
   `content_hash`, скаляры, `kind` и фасеты с владельцем `source`. Ручные и
   производные фасеты не запускают перезапись.
5. **Нет владельца — считается `user`.** Это безопасное умолчание: объект,
   созданный вручную или старым адаптером, не будет молча перезаписан.
6. **`CONTRACT_VERSION = 4`:** адаптеры-источники теперь обязаны размечать
   владельцев; старые источники реестр отклонит с явной причиной.

## Альтернативы

- **Писать скан целиком (как было).** Просто, но уничтожает ручные правки и
  анализ. Отклонено.
- **Не перезаписывать существующие фасеты вообще.** Источник перестаёт
  обновлять свои же данные (например, исправленный в имени автора).
  Отклонено.
- **Хранить диффы/историю правок по фасетам.** Мощно, но это отдельная
  подсистема версионирования; для текущих задач достаточно владельца.
  Отклонено (возможно позже, как ADR-0019+).
- **Определять владельца по провенансу (`derived_by`).** Провенанс есть
  только у анализа; источник и пользователь неразличимы. Отклонено.

## Последствия

Плюсы: ручные правки и результаты анализа выживают пересканирование;
источник обновляет только свои оси; «изменился ли объект» перестаёт
зависеть от чужих фасетов; content-кэш (ADR-0017) получает опору —
производные фасеты помечены.

Минусы: адаптеры обязаны размечать фасеты (ещё одно требование контракта);
удаление фасета источником — окончательное (истории нет); `owners`
увеличивает объект и попадает в контрактные тесты.

## Статус

Принято.
