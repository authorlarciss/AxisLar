# ADR-0022: Пачка пишется целиком или не пишется вовсе

## Контекст

`bulk_upsert` появился в контракте 3 как «быстрая запись набора», и с самого
начала он работал так: проверить каждый объект по отдельности, валидные
записать, ошибки вернуть списком. Именно это закреплял контрактный набор
(`test_bulk_upsert_reports_errors_and_keeps_valid_objects`).

У этой семантики есть дефект, который проявился при работе над пакетным
`apply_plan` (ROADMAP §5.1 продукта). Ссылки в пачке проверяются по
множеству «уже сохранённые + все `id` пачки»: это и позволяет импортировать
связанные заметки в любом порядке. Но если часть пачки отвергнута, объекты,
ссылавшиеся на отвергнутые, всё равно записываются — и получают висячие
ссылки, которые модель прямо запрещает (`DANGLING_REFERENCE`). То есть
гарантия «ссылка может указывать на любой объект пачки» действовала на
входе, но не сохранялась на выходе.

## Решение

1. **`bulk_upsert` атомарен.** Сначала проверяются все объекты пачки,
   запись начинается только если ошибок нет. При любой ошибке в хранилище
   не попадает ничего, а возвращается список всех найденных ошибок.
2. **Контрактный набор и контрактный тест меняются вместе с портом:**
   `test_bulk_upsert_is_atomic` проверяет, что после отказа пачки
   `count()` не изменился и ни один объект пачки не читается.
3. **`apply_plan` использует одну пачку** (`bulk_upsert` вместо цикла
   `upsert`): план импорта связанных заметок применяется целиком, порядок
   действий в плане больше не имеет значения.
4. **Контракт остаётся 5**: сигнатуры и DTO не менялись, меняется только
   семантика отказа. Для реализаций, которые делегируют запись эталонному
   движку (`json`, `sqlite` в AgoraLar), поведение приходит автоматически.

## Альтернативы

- **Оставить частичную запись и валидировать пачку дважды** (в `apply_plan`
  перед вызовом) — дублирует логику движка в вызывающем коде и не спасает
  сторонние реализации.
- **Двухфазный импорт** (сначала объекты без ссылок, потом ссылки) — сложнее
  в вызывающем коде и не чинит дефект самого порта.
- **Запретить ссылки внутри пачки** — убивает главный сценарий: импорт
  заметок со связями.

## Последствия

Плюсы: ссылочная целостность сохраняется после любой записи; вызывающий код
не обязан думать о порядке; пакетный импорт становится одной операцией.

Минусы: частичный успех больше невозможен — при ошибке в одном объекте
отвергается вся пачка, и вызывающий код должен исправлять план целиком.
Для очень больших пачек это означает повторную валидацию при повторе.
Сторонняя реализация, писавшая валидные объекты при ошибках, перестанет
проходить контрактный набор — это осознанно, таких реализаций пока нет.

## Статус

Принято, реализовано в `nu` (контракт 5).
